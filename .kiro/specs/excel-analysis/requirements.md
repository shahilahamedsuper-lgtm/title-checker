# Requirements Document

## Introduction

This feature enhances the Semantic Validator web application with dedicated Excel analysis capabilities. When a user uploads an Excel file (.xlsx or .xls), a new "Analyze Excel" button appears alongside the existing action buttons. Clicking it triggers a backend endpoint that parses the file with pandas, preserving full row/column structure, computes per-column statistics (missing values, duplicate rows, data types), generates an AI-powered narrative summary, and returns all data to a new ExcelDashboard frontend component. The dashboard renders a sortable/filterable data table, bar/pie/line chart visualizations, and summary statistics cards — all within the existing Tailwind CSS design language.

## Glossary

- **Excel_File**: An uploaded file with MIME type `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` (xlsx) or `application/vnd.ms-excel` (xls).
- **Excel_Analysis_Endpoint**: The new FastAPI route `POST /api/analyze-excel` that parses and analyses an Excel_File.
- **Excel_Analysis_Service**: The backend Python service responsible for parsing, statistics computation, and AI summary generation.
- **ExcelDashboard**: The new React component that displays the analysis results returned by the Excel_Analysis_Endpoint.
- **Column_Statistics**: Per-column metadata including data type, missing value count, and unique value count.
- **AI_Summary**: A natural-language paragraph generated by the AI provider describing key patterns and insights in the uploaded dataset.
- **Data_Table**: The tabular view inside ExcelDashboard that renders rows and columns from the parsed Excel_File.
- **Chart**: A visual representation (bar, pie, or line) of column data rendered inside ExcelDashboard.
- **FileUploader**: The existing React component that handles file upload and exposes action buttons after a successful upload.
- **Dashboard**: The existing React page component that coordinates state between FileUploader and other panels.

## Requirements

### Requirement 1: Excel-Only Trigger

**User Story:** As a user, I want an "Analyze Excel" button to appear only when I upload an Excel file, so that I am not confused by irrelevant actions for non-Excel uploads.

#### Acceptance Criteria

1. WHEN an Excel_File is successfully uploaded, THE FileUploader SHALL display an "Analyze Excel" button alongside the existing action buttons.
2. WHEN a non-Excel file (PDF, DOCX, TXT) is successfully uploaded, THE FileUploader SHALL NOT display the "Analyze Excel" button.
3. WHILE the Excel_Analysis_Endpoint is processing a request, THE FileUploader SHALL disable the "Analyze Excel" button and display a loading indicator on it.

---

### Requirement 2: Backend Excel Parsing

**User Story:** As a developer, I want the backend to parse Excel files preserving row/column structure, so that analysis can operate on structured tabular data rather than a flat string.

#### Acceptance Criteria

1. WHEN a valid Excel_File is submitted to the Excel_Analysis_Endpoint, THE Excel_Analysis_Service SHALL parse the file using pandas and return a structured representation containing column headers and all data rows.
2. WHEN an Excel_File contains multiple sheets, THE Excel_Analysis_Service SHALL parse the first sheet only.
3. WHEN an Excel_File exceeds 10 MB, THE Excel_Analysis_Endpoint SHALL return HTTP 422 with a descriptive error message.
4. IF the Excel_File cannot be parsed (corrupt or unsupported format), THEN THE Excel_Analysis_Endpoint SHALL return HTTP 422 with a descriptive error message.
5. WHEN a valid Excel_File is submitted, THE Excel_Analysis_Service SHALL return column headers as a list of strings, with unnamed columns labelled using the pattern `Column_N` where N is the 1-based column index.

---

### Requirement 3: Column Statistics

**User Story:** As a data analyst, I want per-column statistics in the analysis response, so that I can quickly identify data quality issues.

#### Acceptance Criteria

1. WHEN a valid Excel_File is parsed, THE Excel_Analysis_Service SHALL compute, for each column: the inferred data type (one of `"numeric"`, `"text"`, `"date"`, `"boolean"`, `"mixed"`), the count of missing (null or empty) values, and the count of unique non-null values.
2. WHEN a valid Excel_File is parsed, THE Excel_Analysis_Service SHALL compute the total number of duplicate rows across the entire dataset and include this count in the response.
3. WHEN a column contains only numeric values, THE Excel_Analysis_Service SHALL include the minimum, maximum, and mean values (rounded to 2 decimal places) for that column.

---

### Requirement 4: AI-Generated Summary

**User Story:** As a user, I want an AI-generated narrative summary of my dataset, so that I can understand key patterns without manually inspecting every column.

#### Acceptance Criteria

1. WHEN a valid Excel_File is parsed, THE Excel_Analysis_Service SHALL send a structured prompt to the AI provider containing the column names, column statistics, and the first 20 data rows, and SHALL return the AI provider's response as the AI_Summary string.
2. IF the AI provider does not respond within the configured timeout, THEN THE Excel_Analysis_Endpoint SHALL return HTTP 504 with the message `"AI provider timed out."`.
3. IF the AI provider returns a non-200 response, THEN THE Excel_Analysis_Endpoint SHALL return HTTP 502 with the message `"AI provider error."`.
4. WHERE the AI provider is unavailable, THE Excel_Analysis_Endpoint SHALL still return the parsed table data and column statistics with the AI_Summary field set to `null`.

---

### Requirement 5: Analysis Response Contract

**User Story:** As a frontend developer, I want a well-defined JSON response schema from the analysis endpoint, so that I can reliably render the ExcelDashboard.

#### Acceptance Criteria

1. WHEN the Excel_Analysis_Endpoint returns a successful response, THE Excel_Analysis_Endpoint SHALL return HTTP 200 with a JSON body containing: `headers` (list of strings), `rows` (list of lists of scalar values), `column_stats` (list of Column_Statistics objects), `duplicate_row_count` (integer), and `ai_summary` (string or null).
2. THE Excel_Analysis_Endpoint SHALL accept the file via `multipart/form-data` with the field name `file`.
3. WHEN the uploaded file's MIME type is not an Excel type, THE Excel_Analysis_Endpoint SHALL return HTTP 422 with the message `"Only Excel files (.xlsx, .xls) are supported."`.

---

### Requirement 6: ExcelDashboard — Summary Statistics Cards

**User Story:** As a user, I want to see high-level statistics at a glance, so that I can quickly assess the dataset's shape and quality.

#### Acceptance Criteria

1. WHEN ExcelDashboard receives a valid analysis response, THE ExcelDashboard SHALL display a summary card showing the total row count, total column count, total missing value count, and duplicate row count.
2. WHEN the AI_Summary is present in the response, THE ExcelDashboard SHALL display the AI_Summary text in a dedicated card.
3. WHEN the AI_Summary is null, THE ExcelDashboard SHALL display a placeholder message `"AI summary unavailable."` in the summary card.

---

### Requirement 7: ExcelDashboard — Data Table

**User Story:** As a user, I want to browse the raw data in a table with sorting and filtering, so that I can inspect individual records.

#### Acceptance Criteria

1. WHEN ExcelDashboard renders the Data_Table, THE Data_Table SHALL display all column headers and up to 100 rows by default, with pagination controls to navigate remaining rows in increments of 100.
2. WHEN a user clicks a column header in the Data_Table, THE Data_Table SHALL sort all rows by that column in ascending order; clicking the same header again SHALL sort in descending order.
3. WHEN a user types in the global filter input above the Data_Table, THE Data_Table SHALL filter displayed rows to only those containing the search string (case-insensitive) in any cell.
4. WHEN the Data_Table is sorted or filtered, THE Data_Table SHALL reset to the first page of results.

---

### Requirement 8: ExcelDashboard — Chart Visualizations

**User Story:** As a user, I want chart visualizations of my data, so that I can identify distributions and trends visually.

#### Acceptance Criteria

1. WHEN ExcelDashboard renders, THE ExcelDashboard SHALL display a bar chart showing the count of missing values per column.
2. WHEN the dataset contains at least one numeric column, THE ExcelDashboard SHALL display a line chart showing the values of the first numeric column across row indices.
3. WHEN the dataset contains at least one text column with 10 or fewer unique values, THE ExcelDashboard SHALL display a pie chart showing the frequency distribution of values in that column.
4. WHEN no suitable column exists for a chart type (line or pie), THE ExcelDashboard SHALL hide that chart and display no placeholder.
5. THE ExcelDashboard SHALL render all charts using the Recharts library.

---

### Requirement 9: ExcelDashboard — Navigation and Layout

**User Story:** As a user, I want the Excel analysis results to appear in a clean, dedicated view, so that the dashboard does not feel cluttered.

#### Acceptance Criteria

1. WHEN the user clicks "Analyze Excel" in the FileUploader, THE Dashboard SHALL render the ExcelDashboard below the FileUploader card, replacing any existing BeforeAfterPanel or analysis results.
2. WHEN ExcelDashboard is visible, THE ExcelDashboard SHALL provide a tab navigation with at least three tabs: "Summary", "Data Table", and "Charts".
3. WHEN a tab is selected, THE ExcelDashboard SHALL display only the content for that tab.
4. THE ExcelDashboard SHALL follow the existing Tailwind CSS design language (white cards, slate borders, blue accent colour).

---

### Requirement 10: Error Handling in ExcelDashboard

**User Story:** As a user, I want clear error messages when Excel analysis fails, so that I understand what went wrong and can take corrective action.

#### Acceptance Criteria

1. WHEN the Excel_Analysis_Endpoint returns an error response, THE ExcelDashboard SHALL display the error message returned by the endpoint in a styled error banner.
2. WHEN a network error occurs during the analysis request, THE ExcelDashboard SHALL display the message `"Network error — please check your connection and try again."`.
3. WHEN an error is displayed, THE ExcelDashboard SHALL provide a "Dismiss" button that clears the error and returns the FileUploader to its post-upload success state.
